# 趣味实验展示与 Arena：技术选型核实

核实日期：2026-09-10。范围是架构设计；以下产品行为为设计建议，官方能力与限制分别标出。不固定套餐价格或依赖版本，实施时以锁文件和实际部署配置为准。

## 推荐结论

使用 **Next.js App Router + TypeScript + Node.js runtime + PostgreSQL（Neon）+ Drizzle + GSAP ScrollTrigger**，部署为一个 Vercel 项目。页面、开放投票、排行榜和导入脚本都在同一仓库；数据库和素材对象存储是持久化基础设施，不需要单独开发后端服务。首版沿用已有 OSS 素材，存储访问封装为独立模块，后续可替换为 Vercel Blob。

## 官方依据与具体影响

| 核实项        | 官方能力 / 限制                                                                                                                                                                                              | 对本项目的设计建议                                                                                                                                                       |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Next.js 全栈  | App Router 的 `route.ts` 支持自定义请求处理及 GET、POST、PATCH 等 HTTP 方法。[Route Handlers](https://nextjs.org/docs/app/getting-started/route-handlers)                                                    | 在 `app/api` 实现盲测配对、提交投票和素材响应；服务端页面可直接调用数据库模块，无需绕回本项目 HTTP 接口。                                                                |
| Vercel 持久化 | Node.js 是官方 runtime；函数文件系统只读，`/tmp` 是可写临时空间。[Runtimes](https://vercel.com/docs/functions/runtimes)                                                                                      | 投票、素材索引写入 PostgreSQL；不要用本地 JSON、SQLite 文件或进程内 Map 保存生产数据。上传文件放对象存储。                                                               |
| Vercel 长任务 | 函数调用有执行时长上限，超时会返回错误；请求和响应体也有大小限制。[Functions Limits](https://vercel.com/docs/functions/limitations)                                                                          | 请求路径只做短事务。首版展示预生成素材；批量生成、复杂 SVG 转图和排行榜重算采用离线导入或可恢复后台作业。正式实现时再核对所用套餐、runtime 和 Fluid compute 的具体上限。 |
| Neon 连接池   | Neon 将 PgBouncer 集成到连接路径，使用带 `-pooler` 的 endpoint，交易复用数据库连接；连接池不等于无限数据库吞吐。[Neon 官方连接池说明](https://neon.com/blog/survive-thousands-connections)                   | 服务端请求使用 pooled connection，保持事务短小；迁移工具按所选驱动要求使用直连。数据库与 Vercel 函数尽量同区域。                                                         |
| 滚动叙事      | ScrollTrigger 支持将动画进度绑定滚动位置（`scrub`）、固定元素和时间线控制。[ScrollTrigger](https://gsap.com/docs/v3/Plugins/ScrollTrigger/)                                                                  | 用一条分幕时间线表达照片飞入、照片墙、鹈鹕和鳄鱼入场、星舰登场、登舰和火星抵达。首版用分层图片、SVG 与 CSS transform 实现 2.5D；需要真实三维镜头时再加 WebGL。           |
| SVG 展示      | 浏览器在 SVG 图片上下文可限制 JavaScript、外部资源等能力；这些限制不适用于直接打开 SVG 或将其嵌为文档的情形。[MDN：SVG as an image](https://developer.mozilla.org/en-US/docs/Web/SVG/Guides/SVG_as_an_image) | 导入 SVG 视为不可信内容：预生成统一 PNG/WebP 供盲测；确需 SVG 时以图片方式加载经过处理的资源。不要把模型生成的原始 SVG 直接拼进页面 HTML。原始下载与站点交互域隔离。     |

Neon 的连接池文档本次返回抓取器不支持的 `text/markdown`，因此以上连接机制引用已成功读取的 Neon 官方博文，不据其较早的示例配额制定容量承诺。

## 首版范围

根据最新需求，首版完全开放投票，不引入认证库、账户表或个人历史页面。所有有效票进入统计，胜负和平局更新 Elo，都不好单独计数。账户功能后续再设计。

## 应用层必须自行实现的规则

这些是根据项目目标作出的架构建议，不是框架自动提供的保证。

- **盲测信息隔离**：投票前只返回不透明配对 ID 和匿名图片路径。模型名不能藏在图片 URL、文件名、alt 文本或前端完整数据里；提交后再由服务端解盲。画面中本身出现的模型自署名需要在入库时标记。
- **投票完整性**：配对由服务端生成并附带随机凭证；一轮只提交一次，数据库唯一约束兜底。保存随机左右位置和完整投票事件，支持从原始票重新计算榜单。
- **可比较性**：按实验、提示词版本和输出类型分榜。鹈鹕与星舰解剖图不混为同一质量指标；主观视觉偏好与科学准确性也应分别表达。
- **动画可用性**：尊重 `prefers-reduced-motion`，移动端降低素材数与视差；提供跳过故事、直接 Arena 的入口。首页照片墙使用缩略图，不能一次下载所有原始 SVG。

## 实施前需要通过的针对性验证

1. 使用两个未登录浏览器完成投票，确认有效票均进入对应统计。
2. 并发重试同一场投票，确认只计一次；校验错误凭证、过期配对及不同选择重试的处理。
3. 检查投票前网络响应、HTML 和图片 URL，确认不暴露模型身份。
4. 在低性能移动设备及减少动态效果设置下，确认故事可跳过、Arena 可直接使用。
