# 首版实现记录

本文件描述实际实现；architecture.md 和 experience.md 中未列入这里的项目仍属于设计规划。

## 当前系统

Next.js 16 App Router / React / TypeScript，GSAP ScrollTrigger，Drizzle + PostgreSQL。开发默认用持久化 PGlite，部署 Vercel 时强制要求 DATABASE_URL。全站无登录、账户或个人历史。

已完成首页、实验目录/详情、Arena 与按实验排名。开放投票的配对与写入接口位于 `/api/arena`；图片经 `/api/media` 提供；公开汇总来自 `/api/leaderboard`。

主站叙事插画均原创。火星背景使用内置 ImageGen 生成，原始输出为 1536×1024，项目版本经 WebP 压缩。手绘 SVG 角色、车辆、舰体与引擎在代码中分层。公路、星光与尾焰由代码生成，不请求网络素材或字体。

## 素材导入实测

29 个模型作品全部成功导入，生成 28 个不同内容的预览文件。`kimi-k2.7-code` 与 `DeepSeek-V3` 的来源文件内容一致，但属于两个独立模型记录，使用不同作品 ID。全套作品约 1 MB；火星背景约 200 KB。已验证 HTTPS 获取与 SVG 渲染。模型名称按用户数据保留，没有猜测或修正型号。

导入器仅在全部作品成功时原子替换 catalog；失败项单独报告并返回失败码，保留原 catalog。生产发布不能更换某个已有作品 ID 的图像含义，内容变化必须生成新 ID。

## 评分与事务

在同一实验配对不同模型，随机左右位置，并混合均匀随机与低曝光作品。服务器生成高熵对战凭证，仅存 hash；提交后公开模型信息。凭证不等于账户，不跟踪个人历史。

Vote.battleId 唯一。事务锁定 battle，重复相同选择返回原结果，不同选择返回冲突。评分行按稳定 ID 顺序加锁，记录更新前后值；每个实验的全部有效胜负/平局更新 Elo，都不好只记录拒绝。基础限流共享数据库，Vercel 使用平台提供的转发 IP，开发时统一使用 local 桶，不保存原始 IP。

原始来源的旧分数未导入，开发浏览器测试写入隔离数据库。源码包含评分事件审计，尚未提供运营用作弊审核、评分重算界面或定时快照；这些是后续扩展。

## 验证边界

- 服务层使用真实 PGlite 执行数据库事务测试，覆盖并发、幂等、错误凭证、过期、平局/拒绝、限流、作品 ID 冲突。
- 浏览器端在 Chrome 桌面与手机尺寸验证首页和完整投票流程，测试使用独立数据库。
- 生产构建和 TypeScript 检查通过后可部署；实际外部 PostgreSQL、Vercel 地区/连接与生产域名仍需部署时验证。
- 当前不承诺线上 LCP/INP 或所有真实手机帧率；文档中的性能数值是目标，不是已完成的线上测量。
